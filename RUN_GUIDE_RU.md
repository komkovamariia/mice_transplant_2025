# Полный порядок запуска и структура анализа

Этот файл является единственным русскоязычным руководством в активной версии репозитория. Весь исполняемый код, комментарии в notebooks, подписи графиков и англоязычная документация оформлены на английском.

## 1. Что анализируется

В проекте есть три независимых аналитических подхода и четвёртый этап, который сравнивает их результаты. Все три подхода используют одну каноническую таблицу клонотипов `clean_clonotypes_aaV.parquet`, поэтому расхождения между методами не возникают из-за разных исходных наборов образцов.

Каждый подход отдельно выполняется для шести заранее заданных страт:

1. `cd4_thymus` — CD4, тимус.
2. `cd4_spleen` — CD4, селезёнка.
3. `cd8_thymus` — CD8, тимус.
4. `cd8_spleen` — CD8, селезёнка.
5. `cd4_combined` — CD4, тимус и селезёнка вместе.
6. `cd8_combined` — CD8, тимус и селезёнка вместе.

В объединённых стратах не смешиваются CD4 и CD8. Объединяются только два компартмента одного клеточного типа.

## 2. Где что находится

`approaches/01_set_count/` содержит первый подход. Он работает с точными aaV-клонотипами и отвечает на вопрос, какие клонотипы и V-сегменты отличаются по наличию и количеству.

`approaches/02_sequence_embedding/` содержит второй подход. Он переводит TCR-последовательности в общее пространство признаков и отвечает на вопрос, какие локальные области sequence space и какие целые репертуары смещены между группами.

`approaches/03_clone_alloreactivity/` содержит третий подход. Он ранжирует отдельные клонотипы по нескольким независимым признакам аллогенного смещения.

`approaches/04_cross_approach/` не является четвёртым биологическим методом. Это итоговый слой сравнения первых трёх подходов.

`src/` содержит вычислительную логику. Notebooks сделаны короткими и читаемыми: в них видно последовательность этапов, а тяжёлые и повторно используемые функции вынесены в Python-модули.

`scripts/run_analysis.py` запускает notebooks по ячейкам, пишет журнал выполнения и сохраняет checkpoint после каждой успешно завершённой кодовой ячейки.

`figures/` является единственным корневым каталогом для графиков. Внутри он разделён по подходам и затем по биологическим стратам.

`outputs/tables/` содержит все численные результаты. `outputs/notebooks/` содержит выполненные notebooks. `outputs/logs/` содержит журналы. `outputs/cache/` используется для тяжёлых промежуточных объектов, которые безопасно переиспользовать при повторном запуске.

По умолчанию ожидается файл:

```text

```

Минимально необходимы колонки:

```text

v_gene
umi

```

Если данные лежат в другом месте:

```bash

```

или можно указать непосредственно файл:

```bash
export MICE_TCR_CLEAN_PARQUET=/полный/путь/clean_clonotypes_aaV.parquet
```

До тяжёлого анализа код проверяет, что для каждой страты действительно нашлись образцы. CD4/CD8 определяется по `subtype`, при необходимости используется `sample_id`. Тимус/селезёнка определяется по `source`, при необходимости также используется `sample_id`. Неопределившиеся образцы не добавляются в страту молча.

## 5. Подход 1: exact sets + edgeR/Fisher

Notebook:

```text
approaches/01_set_count/set_count_analysis.ipynb
```

Запуск:

```bash
python scripts/run_analysis.py --approach 1
```

Последовательность внутри notebook:

1. Загружается каноническая таблица и проверяются шесть страт.
2. Для каждой страты формируются точные aaV-клонотипы, где ключом является `CDR3aa + V`.
3. Для g1, g5 и g6 строятся множества. Отдельно определяется область клонотипов, присутствующих в g1 и отсутствующих в g5/g6.
4. На уровне отдельных sample строится count matrix.
5. edgeR сравнивает g1 с объединённым allogeneic reference g5+g6 через quasi-likelihood модель.
6. Для тех же count data выполняется Fisher exact test как независимая проверка.
7. Клонотипы агрегируются по V-сегментам. Основное ранжирование строится по числу edgeR-significant aaV features, при этом сохраняются effect size, Fisher/edgeR consensus и поддержка g1-exclusive set.
8. Для каждой страты создаётся отдельный JSON с кратким выводом и отдельная таблица V-ranking.

Что получается: для каждого клеточного типа и компартмента видно, какие точные клонотипы меняют abundance и какие V-сегменты несут наиболее повторяемый count-based signal.

Почему подход нужен: он максимально близок к исходной логике статьи и не использует similarity между разными CDR3. Последовательности считаются либо одинаковыми, либо разными.

## 6. Подход 2: sequence embedding + density + MMD

Notebook:

```text
approaches/02_sequence_embedding/sequence_embedding_analysis.ipynb
```

Запуск:

```bash
python scripts/run_analysis.py --approach 2
```

Последовательность:

1. Загружается та же каноническая таблица.
2. Один раз строится общий TCREmp/PCA basis для всех уникальных aaV-клонотипов. Это техническая система координат, а не объединённый биологический тест.
3. Basis и координаты сохраняются в cache. Поэтому после ошибки повторный запуск не обязан заново считать embedding, если набор клонотипов не изменился.
4. Для каждой из шести страт независимо выполняется exact k-d-tree density enrichment: g1 сравнивается с allogeneic background g5+g6.
5. Значимыми считаются локальные sequence-space enrichment с q-value < 0.05 и fold > 1.
6. Enriched clonotypes агрегируются по V-сегментам.
7. Для каждого sample строится RFF representation репертуара. Из него рассчитывается MMD matrix.
8. Для MMD выполняется исправленный deterministic PERMANOVA с 9 999 перестановками. Перестановки генерируются до распараллеливания, поэтому результат не зависит от порядка завершения worker-процессов.
9. Строится witness direction между g1 и g5+g6 и ранжируются отдельные g1-клонотипы, которые сильнее всего направлены вдоль этого различия.
10. Для enriched последовательностей создаётся компактная motif/convergence summary.

Что получается: отдельное для каждой страты доказательство на двух масштабах, локальные sequence neighborhoods и геометрия целого репертуара.

Почему подход нужен: точный count-based подход не видит, что две разные CDR3 могут быть очень похожи. Embedding анализирует структуру sequence space, поэтому является методологически независимой проверкой.

Важно: старые PERMANOVA p-values из исторического notebook использовать нельзя. В старой функции permuted labels фактически игнорировались. В публикационные таблицы должны попадать только значения, пересчитанные текущей версией.

## 7. Подход 3: clone-level prioritization

Notebook:

```text
approaches/03_clone_alloreactivity/clone_alloreactivity_analysis.ipynb
```

Запуск:

```bash
python scripts/run_analysis.py --approach 3
```

Последовательность:

1. Для каждой страты отдельно собирается присутствие каждого клонотипа по мышам.
2. Считается доля g1-мышей и доля allogeneic g5/g6-мышей, в которых наблюдается клонотип.
3. Считается abundance shift между allogeneic samples и g1.
4. Для клонотипов одного V-сегмента оценивается локальная CDR3 convergence, количество последовательностей той же длины на Hamming distance 1.
5. Дополнительно рассчитываются длина CDR3, средняя hydrophobicity и приблизительный net charge. Они используются для интерпретации, но не считаются доказательством антигенной специфичности.
6. Независимые сигналы prevalence, abundance и convergence переводятся в percentile ranks и объединяются в integrated prioritization score.
7. Отдельно сохраняются все evidence features, список candidate clonotypes и V-segment ranking.
8. Для каждой страты формируется отдельный краткий вывод.

Почему подход нужен: первые два подхода в основном отвечают на вопрос о групповых и V-level сдвигах. Третий подход переводит результат на уровень отдельных клонотипов, которые можно приоритизировать для дальнейшей экспериментальной проверки.

Integrated score не является вероятностью того, что клон аллореактивен, и не должен так описываться в статье.

## 8. Финальное сравнение подходов

Notebook:

```text
approaches/04_cross_approach/cross_approach_comparison.ipynb
```

Запуск после первых трёх:

```bash
python scripts/run_analysis.py --approach 4
```

Для каждой страты отдельно:

1. Загружаются три V-segment ranking.
2. Считаются pairwise Spearman correlations.
3. Считается пересечение top-10.
4. Rank внутри каждого подхода нормируется относительно длины его ranking.
5. Строится consensus rank без искусственного требования полного совпадения.
6. В финале считается, сколько раз V-сегмент входит в top-5 consensus across the six strata.

Получается итог, в котором можно отличить общий устойчивый сигнал от эффекта, специфичного для CD4/CD8 или тимуса/селезёнки.

## 10. Логи и контроль процесса

Runner не ждёт завершения всего notebook, чтобы сообщить о прогрессе. Перед каждой кодовой ячейкой он записывает её номер, общее число ячеек и сколько останется после неё. После завершения записывает время выполнения.

Если ячейка работает долго, каждые 30 секунд появляется heartbeat:

```text
[CELL 003/009] RUNNING | elapsed=300s
```

Смотреть лог в реальном времени:

```bash
tail -f outputs/logs/02_sequence_embedding.log
```

После каждой успешно выполненной кодовой ячейки сохраняется checkpoint:

```text
outputs/notebooks/<approach>.executed.ipynb
```

Это принципиально отличается от обычного `jupyter nbconvert --execute`: при падении поздней ячейки уже выполненная часть не исчезает.

## 11. Продолжение после ошибки

Для повторного запуска с checkpoint:

```bash
python scripts/run_analysis.py --approach 2 --resume
```

При resume bootstrap cells выполняются заново, чтобы восстановить Python state. Уже завершённые аналитические ячейки пропускаются, если их ID есть в checkpoint. Результаты тяжёлых этапов должны существовать на диске, а Approach 2 дополнительно использует cache общего embedding basis.

Поэтому после поздней ошибки больше не требуется автоматически пересчитывать весь notebook с нуля.

## 13. Что считать главным результатом

Не следует выбирать один V-сегмент только потому, что он стал значимым в одном тесте. Наиболее сильная публикационная логика состоит из трёх уровней:

1. Внутри одной страты сигнал поддерживается несколькими независимыми подходами.
2. Направление эффекта и V-ranking не противоречат друг другу.
3. Сигнал повторяется в нескольких биологически связанных стратах, либо его compartment specificity имеет содержательное биологическое объяснение.

Таким образом, финальный cross-approach notebook является не дополнительным статистическим тестом, а контролируемым слоем интеграции независимых результатов.
